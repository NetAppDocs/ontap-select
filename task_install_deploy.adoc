= Install ONTAP Select Deploy
:hardbreaks:
:nofooter:
:icons: font
:linkattrs:
:imagesdir: ./media/

[.lead]
You need to install the ONTAP Select Deploy administration utility and use the utility to create an ONTAP Select cluster.

.Before you begin

You have reviewed the pre-installation checklist for your hypervisor host:

* link:esxi-host-configuration-and-preparation-checklist.html[ESXi host checklist]
* link:hyper-v-host-configuration-and-preparation-checklist.html[Hyper-V host checklist]
* link:kvm-host-configuration-and-preparation-checklist.html[KVM host checklist]

== Step 1: Download the virtual machine image

Download the ONTAP Select package from the NetApp support site.

.Before you begin
https://mysupport.netapp.com/site/user/registration[You have a registered NetApp Support Site account^].


.About this task
The ONTAP Select Deploy administration utility is packaged as a virtual machine (VM) based on the Open Virtualization Format. The single compressed file has the suffix `ova` for ESXi hosts, `vhdx.tgz` for Hyper-V and `raw.tgz` for KVM hosts. The VM provides the Deploy server and installation images for ONTAP Select nodes.

.Steps
. Access the link:https://mysupport.netapp.com/site/downloads/[NetApp Support Site downloads^] page.

. Scroll down and select *ONTAP Select Deploy*.

. Select the desired ONTAP Select version.

. Review the End User License Agreement (EULA) and select *Accept & Continue*.

. Select and download the appropriate *ONTAP Select Deploy Install* package. Respond to all prompts as needed.

== Step 2: Verify the ONTAP Select Deploy OVA signature

Verify the ONTAP Select Open Virtualization Appliance (OVA) signature before installing the installation package.

.Before you begin
Verify that your system meets the following requirements:

* OpenSSL versions 1.0.2 to 3.0 for basic verification
* Public internet access for Online Certificate Status Protocol (OCSP) verification

.Steps

. Obtain the following files from the product download page on the NetApp support site:
+
[cols=2*,options="header"]
|===
| File
| Description
| `ONTAP-Select-Deploy-Production.pub`
| The public key used to verify the signature.
| `csc-prod-chain-ONTAP-Select-Deploy.pem`
| The public certification authority (CA) chain of trust.
| `csc-prod-ONTAP-Select-Deploy.pem`
| The certificate used to generate the key.
| `ONTAPdeploy.ova`
| The product installation executable for ONTAP Select.
| `ONTAPdeploy.ova.sig`
| The SHA-256 algorithm is hashed and then signed by the Remote Support Agent (RSA) using the `csc-prod` key and signature for the installer.
|===

. Verify that the `ONTAPdeploy.ova.sig` file is using the associated certificates and validation commands.

. Verify the signature:
+
[source,cli]
----
openssl dgst  -sha256 -verify ONTAP-Select-Deploy-Production.pub -signature ONTAPdeploy.ova.sig  ONTAPdeploy.ova
----
 

== Step 3: Deploy the virtual machine

Create the ONTAP Select Deploy virtual machine on your hypervisor host.

[role="tabbed-block"]
====
.ESXi
--
Install and start the ONTAP Select Deploy VM on an ESXi host using the OVF VM image. As part of the installation process, you configure the network interface to use DHCP or a static IP configuration.

.Before you begin

You must prepare to deploy the ONTAP Select Deploy VM:

* Enable the OVF functionality in your browser by installing the VMware Client Integration Plugin or performing similar configuration as needed
* Enable the DHCP in the VMware environment if you will dynamically assign an IP address to the Deploy VM

You must have the configuration information to be used when creating the VM, including the name of the VM, external network, and host name. When defining a static network configuration, you need the following additional information:

* IP address of the Deploy VM
* Netmask
* IP address of the gateway (router)
* IP address of the primary DNS server
* IP address of the second DNS server
* DNS search domains

.About this task
If you use vSphere, the Deploy OVF template wizard includes a form to provide all of the Deploy configuration information, including the network configuration. However, if you choose not to use this form, you can use the console of the Deploy VM to configure the network instead.

.Steps

. Access the vSphere client and sign in.

. Navigate to the appropriate location in the hierarchy and select *Deploy OVF Template*.

. Select the OVA file and complete the Deploy OVF Template wizard. Select the options that are appropriate for your environment.
+
You must define the password for the administrator account. You need to provide this password when signing in to the Deploy utility.

. After the VM is deployed, select the new VM. If it isn't already powered on based on your input to the deployment wizard, power it on manually.

. If needed, you can configure the Deploy network using the VM console:
.. Select the *Console* tab to access the ESXi host setup shell and monitor the power on process.
.. Wait for the following prompt:
+
Host name :
.. Type the host name and select *Enter*.
.. Wait for the following prompt:
+
Provide a password for the admin user:
.. Type the password and select *Enter*.
.. Wait for the following prompt:
+
Use DHCP to set networking information? [n]:
.. Type *n* to define a static IP configuration or *y* to use the DHCP, and select *Enter*.
.. If you choose a static configuration, provide all the required network configuration information.
--
.Hyper-V
--
Install and start the ONTAP Select Deploy VM on a Hyper-V host using a VHDX VM image. During the installation, you configure the network interface to use DHCP or a static IP configuration.

.Before you begin
Verify that the Hyper-V host meets the following requirements: 

[cols="1,2",options="header"]
|===
|Requirement
|Value

|Hyper-V role
|Installed, including the Hyper-V PowerShell module

|VM generation
|Generation 1

|vCPUs
|2

|Memory
|4 GB, static (dynamic memory disabled)

|Boot disk
|Attached to IDE Controller 0, Location 0

|Free disk space
|At least 20 GB on the volume that stores the VM disk

|Archive tool
|tar, included with Windows Server 2019 and later
|===

Verify that you have the following information:

[cols="1,2",options="header"]
|===
|Information
|Description

|VM name
|Name of the Deploy VM, for example ONTAP-deploy-HV

|Virtual switch name
|Name of the external virtual switch, for example ONTAP_Vswitch

|Physical NIC name
|Host network adapter connected to the Deploy VM network

|VLAN ID
|Required only if the upstream switch port expects tagged traffic

|Host name
|FQDN or short host name of the Deploy VM

|Administrator password
|Password for the admin account, set during first boot
|===

When defining a static network configuration, you need the following additional information:

* IP address of the Deploy VM
* Netmask
* IP address of the gateway (router)
* IP address of the primary DNS server
* IP address of the second DNS server
* DNS search domains

.About this task
Run the commands from a PowerShell session on the Hyper-V host.

Creating an external virtual switch briefly interrupts network traffic on the physical NIC. If you're connected to the host remotely over the physical NIC, use an out-of-band console (such as the server BMC) or a different network adapter so you don't lose access. 

.Steps
. On the Hyper-V host, open a PowerShell session with Run administrator privileges.
. Confirm that the `Hyper-V` role is installed: 
+
[source,cli]
----
Get-WindowsFeature -Name Hyper-V, Hyper-V-PowerShell 
----
+
If the value for `Install State` is not `Installed`, install the role and restart the host: 
+
[source,cli]
----
Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart 
----
  
. Create the external virtual switch: 

.. Identify the physical adapter connected to the Deploy VM network and record the adapter name for use later in the procedure: 
+
[source,cli]
----
Get-NetAdapter | Select-Object Name, InterfaceDescription, Status 
----

.. A physical adapter can be bound to only one external switch. Check for existing external virtual switches: 
+
[source,cli]
----
Get-VMSwitch -SwitchType External 
----
+
* If there is no switch bound to the adapter you identified, <<create-external-vswitch,create the external virtual switch>>.
* If a switch is already bound to the adapter you identified, proceed to <<extract-image,extract the VHDX image>> and use the bound switch name in the remaining steps.

.. [[create-external-vswitch]]Create the external virtual switch, replacing `<physical_nic_name>` with the adapter name: 
+
[source,cli]
----
New-VMSwitch -Name "<virtual_switch_name>" -NetAdapterName "<physical_nic_name>" -AllowManagementOS $true
----
+  
The `-AllowManagementOS $true` parameter allows the host to keep using the physical adapter through a virtual adapter named vEthernet (<virtual_switch_name>). 

.. Confirm that the host management IP address moved to the virtual adapter: 
+
[source,cli]
----
Get-NetIPAddress -InterfaceAlias "vEthernet (<virtual_switch_name>)" -AddressFamily IPv4
---- 

.. If the host IP address is missing or incorrect, reassign it: 
+
[source,cli]
----
New-NetIPAddress -InterfaceAlias "vEthernet (<virtual_switch_name>)" -IPAddress "<host_IP_address>" -PrefixLength <prefix_length> -DefaultGateway "<gateway_IP_address>" 
Set-DnsClientServerAddress -InterfaceAlias "vEthernet (<virtual_switch_name>)" -ServerAddresses "<primary_dns>","<secondary_dns>" 
----
  
.. Verify that the host can reach the gateway: 
+
[source,cli]
----
ping <gateway_IP_address> 
----
  
. [[extract-image]]Extract the VHDX image: 

.. Confirm that the target volume has at least 20 GB free: 
+
[source,cli]
----
Get-Volume -DriveLetter D | Select-Object DriveLetter, SizeRemaining 
----
  
.. Create the storage folders for the virtual disk and the VM configuration files: 
+
[source,cli]
----
New-Item -ItemType Directory -Path "<storage_location>\Disks" -Force 
New-Item -ItemType Directory -Path "<storage_location>\VMs" -Force 
----
  
.. Copy the downloaded package to the disks folder, replacing `<download_path>` with the folder that contains the package: 
+
[source,cli]
----
Copy-Item -Path "<download_path>\ONTAPdeploy.vhdx.tgz" -Destination "<storage_location>\Disks" 
----
  
.. Extract the archive: 
+
[source,cli]
----
Set-Location <storage_location>\Disks 
tar -xzf ONTAPdeploy.vhdx.tgz 
----
  
.. Confirm that the virtual disk was extracted: 
+
[source,cli]
----
Get-ChildItem -Path "<storage_location>\Disks\ONTAPdeploy.vhdx" 
----
  
. Create and configure the VM: 

.. Create a `Generation 1` VM without a virtual disk: 
+
[source,cli]
----
New-VM -Name "<VM_name>" -Generation 1 -MemoryStartupBytes 4GB -Path "<storage_location>\VMs" -NoVHD 
----
  
.. Set the processor count and disable dynamic memory: 
+
[source,cli]
----
Set-VMProcessor -VMName "<VM_name>" -Count 2 
Set-VMMemory -VMName "<VM_name>" -DynamicMemoryEnabled $false -StartupBytes 4GB 
----
  
.. Attach the VHDX as the boot disk on the IDE controller: 
+
[source,cli]
----
Add-VMHardDiskDrive -VMName "<VM_name>" -ControllerType IDE -ControllerNumber 0 -ControllerLocation 0 -Path "<storage_location>\Disks\ONTAPdeploy.vhdx"
---- 
+
CAUTION: A Generation 1 VM only boots from an IDE controller. The VM won't start if you attach the boot disk to a SCSI controller. 

.. Connect the VM network adapter to the virtual switch: 
+
[source,cli]
----
Connect-VMNetworkAdapter -VMName "<VM_name>" -Name "Network Adapter" -SwitchName "<virtual_switch_name>"
----  

.. Configure the VLAN setting to match the upstream switch port: 

* If the port is untagged: 
+
[source,cli]
----
Set-VMNetworkAdapterVlan -VMName "<VM_name>" -VMNetworkAdapterName "Network Adapter" -Untagged 
----
* If the port expects tagged traffic: 
+
[source,cli]
----
Set-VMNetworkAdapterVlan -VMName "<VM_name>" -VMNetworkAdapterName "Network Adapter" -Access -VlanId <vlan_ID> 
----
  
.. Enable `MAC address spoofing` on the VM network adapter: 
+
[source,cli]
----
Set-VMNetworkAdapter -VMName "<VM_name>" -MacAddressSpoofing On 
----
  
.. Review the VM configuration: 
+
[source,cli]
----
Get-VM -Name "<VM_name>" | Select-Object Name, Generation, ProcessorCount, MemoryStartup, DynamicMemoryEnabled 
Get-VMHardDiskDrive -VMName "<VM_name>" 
Get-VMNetworkAdapter -VMName "<VM_name>" | Select-Object Name, SwitchName, MacAddressSpoofing 
Get-VMNetworkAdapterVlan -VMName "<VM_name>" 
----
+
Confirm that the output shows the following configuration: 

* Generation: *Generation 1*
* ProcessorCount: *2*
* MemoryStartup: *4 GB*
* DynamicMemoryEnabled: *Disabled*
* VMHardDiskDrive:
** ControllerNumber: *0*
** ControllerLocation: *0*
* VMNetworkAdapter: 
** SwitchName: *<virtual_switch_name>* 
** MAC address spoofing: *On*
* VMNetworkAdapterVlan: *untagged* or *<vlan_ID>*

. Start the VM and complete the first boot: 

.. Start the VM: 
+
[source,cli]
----
Start-VM -Name "<VM_name>"
----
.. Open the VM console: 
+
[source,cli]
----
vmconnect.exe localhost "<VM_name>" 
----
+
Alternatively, open the console from Hyper-V Manager by right-clicking on the VM and selecting *Connect*.

.. Respond to the boot prompts: 
+
[cols="1,2",options="header"]
|===
|Prompt
|Action

|Host name:
|Enter the Deploy VM host name, then select Enter.

|Provide a password for the admin user:
|Enter the administrator password, then select Enter.

|Use DHCP to set networking information? [n]:
|Enter `y` to use DHCP or `n` to define a static IP configuration, then select Enter.
|===

.. If you chose a static configuration, provide the IP address, netmask, gateway, DNS servers, and DNS search domain when prompted. 

.. Wait for the VM to finish booting. 
+
NOTE: A gateway warning might display during the first boot. If this occurs, the VM can still configure correctly and you can verify connectivity in the next step. 

. Verify that the Deploy VM is running and reachable: 

.. On the Hyper-V host, confirm that the VM state is `Running`:
+
[source,cli]
----
Get-VM -Name "<VM_name>" | Select-Object Name, State, Uptime 
----

.. From a system on the same network, ping the Deploy VM. If you used DHCP, get the assigned IP address from your DHCP server:
+ 
[source,cli]
----
ping <deploy_vm_IP_address> 
----
--
.KVM
--
Install and start the ONTAP Select Deploy VM on a KVM host using the OVF VM image. As part of the installation process, you configure the network interface to use DHCP or a static IP configuration.

.Before you begin

You must have the configuration information to be used when creating the VM, including the name of the VM, external network, and host name. When defining a static network configuration, you need the following additional information:

* IP address of the Deploy VM
* Netmask
* IP address of the gateway (router)
* IP address of the primary DNS server
* IP address of the second DNS server
* DNS search domains

.Steps

. Sign in to the CLI at the Linux server:
+
----
ssh root@<ip_address>
----

. Create a new directory and extract the raw VM image:
+
----
mkdir /home/select_deploy25
cd /home/select_deploy25
mv /root/<file_name> .
tar -xzvf <file_name>
----

. Create and start the KVM VM running the Deploy administration utility:
+
----
virt-install --name=select-deploy --vcpus=2 --ram=4096 --os-variant=debian10 --controller=scsi,model=virtio-scsi --disk path=/home/deploy/ONTAPdeploy.raw,device=disk,bus=scsi,format=raw --network "type=bridge,source=ontap-br,model=virtio,virtualport_type=openvswitch" --console=pty --import --noautoconsole
----
. If needed, you can configure the Deploy network using the VM console:
.. Connect to the VM console:
+
----
virsh console <vm_name>
----

.. Wait for the following prompt:
+
----
Host name :
----

.. Type the host name and select *Enter*.
.. Wait for the following prompt:
+
----
Use DHCP to set networking information? [n]:
----

.. Type *n* to define a static IP configuration or *y* to use the DHCP, and select *Enter*.
.. If you choose a static configuration, provide all network configuration information as required.
--

== Step 4: Sign in to the Deploy web interface

Sign in to the web user interface to confirm the Deploy utility is available and perform the initial configuration.

.Steps
. Point your browser to the Deploy utility using the IP address or domain name:
+
`\https://<IP_address>/`

. Provide the administrator (admin) account name and password and sign in.

. If the *Welcome to ONTAP Select* pop-up window is displayed, review the prerequisites and select *OK* to continue.

. If this is the first time signing in and you did not install Deploy using the wizard available with vCenter, provide the following configuration information when prompted:
+
* New password for the administrator account (required)
* AutoSupport (optional)
* vCenter server with account credentials (optional)
